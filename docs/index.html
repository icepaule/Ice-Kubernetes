Ueberblick

Ice-Kubernetes ist das GitOps-Repository fuer einen privat betriebenen K3s-Cluster: Statt einzelne Docker-Compose-Stacks manuell auf verschiedenen Hosts zu pflegen, werden Anwendungen schrittweise als Kubernetes-Manifeste hierher migriert und von ArgoCD automatisch auf den Cluster ausgerollt. Ein Server-Node uebernimmt Control-Plane und Kern-Plattform, ein Agent-Node mit GPU bedient rechenintensive Workloads, waehrend ausgewaehlte Legacy-Docker-Hosts nur noch ueberwacht statt migriert werden.

GitOps mit ArgoCD

App-of-Apps-Pattern: ein Wurzel-Application-Objekt verwaltet alle Workload-Applications. Ein Push auf den Hauptbranch wird automatisch auf den Cluster synchronisiert.

Modulare App-Manifeste

Jeder Workload liegt als eigenes Kustomize-Verzeichnis unter manifests/apps/ — von einfachen Single-Container-Diensten bis zu mehrteiligen Stacks mit eigener Datenbank und Queue.

Monitoring-Stack

kube-prometheus-stack ueberwacht Cluster-Nodes und Pods automatisch; externe Docker-Hosts werden per node-exporter/cAdvisor zusaetzlich eingebunden.

Schrittweise Migration

Bestehende Compose-Stacks werden priorisiert nach Komplexitaet migriert; Dienste, die eng an ein bestehendes Host-System gebunden sind, bleiben bewusst dort.

Aenderungen an Kubernetes-Manifesten werden ausschliesslich ueber Git eingecheckt. ArgoCD beobachtet dieses Repository im App-of-Apps-Muster und rollt jede App als eigene ArgoCD-Application automatisch auf den K3s-Cluster aus. Der Server-Node traegt Control-Plane und Kern-Plattform (MetalLB fuer LoadBalancer-Services, Ingress, ArgoCD selbst), ein separater Agent-Node mit GPU uebernimmt rechenintensive Workloads. Persistenter Speicher kommt ueber einen NFS-Provisioner, die Beobachtung von Cluster und externen Docker-Hosts laeuft zentral ueber den Monitoring-Stack.

Quickstart

Ausfuehrliche Schritt-fuer-Schritt-Anleitungen liegen unter docs/01-prerequisites.md bis docs/08-admin-guide.md im Repository. Grober Ablauf:

git clone https://github.com/icepaule/Ice-Kubernetes.git
cd Ice-Kubernetes

# Core-Plattform nach K3s-Setup ausrollen
kubectl apply -f manifests/namespaces.yaml
helm install metallb metallb/metallb -n metallb-system --create-namespace \
  -f helm-values/metallb-values.yaml

# GitOps aktivieren (App-of-Apps)
kubectl apply -f manifests/core/argocd/app-of-apps.yaml
